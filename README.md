# CORDIC activation functions

[![Octave tests](https://github.com/linabenlahsar/Optimisation-des-Fonctions-d-Activation-pour-les-R-seaux-de-Neurones-par-Algorithme-CORDIC/actions/workflows/octave.yml/badge.svg)](https://github.com/linabenlahsar/Optimisation-des-Fonctions-d-Activation-pour-les-R-seaux-de-Neurones-par-Algorithme-CORDIC/actions/workflows/octave.yml)

This project started as an engineering-school study carried out with **Fatima-Ezzahra Ahchouch**. We used a neural-network model of a full adder as a small test case, then compared several ways of approximating `tanh` and `sigmoid` for an FPGA-oriented implementation.

This repository contains the numerical part of the work in MATLAB/Octave. It compares:

- a hyperbolic CORDIC implementation;
- a uniformly sampled lookup table, with or without interpolation;
- truncated Taylor series.

The aim is to understand the accuracy and implementation trade-offs before moving to fixed-point RTL.

## CORDIC implementation

The hyperbolic core repeats iterations 4, 13, 40, … as required for convergence. Inputs outside the core interval are reduced by repeated halving, then reconstructed with

`tanh(2x) = 2 tanh(x) / (1 + tanh²(x))`.

The ratio `y/x` is used directly, so the hyperbolic gain cancels.

## Reference result

The current regression evaluates 4,001 samples over `[-4, 4]` in double precision.

| Configuration | MSE | Mean absolute error | Maximum absolute error |
|---|---:|---:|---:|
| Hyperbolic CORDIC, 16 iterations | 1.63e-11 | 2.48e-6 | 1.50e-5 |

These figures are generated by the software reference model. They are not fixed-point, RTL, synthesis, timing, area, or power results.

## Running the project

With MATLAB:

```matlab
run_demo
```

With GNU Octave:

```bash
octave --no-gui --quiet run_demo.m
```

The command runs the regression tests and regenerates the comparison plots. Tests can also be launched separately:

```matlab
addpath('src');
addpath('tests');
run_tests;
```

## Files

- `src/`: CORDIC, LUT, Taylor, sigmoid, and error-metric functions
- `experiments/`: method comparison and parameter sweeps
- `tests/`: deterministic numerical checks
- `docs/methodology.md`: equations, assumptions, and hardware limitations
- `run_demo.m`: entry point

## Next hardware steps

A complete FPGA implementation would still need a chosen fixed-point format, rounding and saturation rules, an iterative or pipelined micro-architecture, and post-synthesis measurements.
